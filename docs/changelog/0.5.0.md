# [0.5.0] — PROPOSED (unreleased)

Multi-keyspace support: one `install(Kandra)` and one `CqlSession` (one connection pool) can serve
many keyspaces. Backward compatible; no config or CQL change for single-keyspace applications.

> Status: this is the changelog for the work on `feature/multi-keyspace`. The build files still say
> `0.4.8` (`gradle.properties`); nothing here is released or published yet.

### Added

- `@ScyllaTable(keyspace = "")` — the keyspace is a property of the entity, set at compile time.
  Blank means the plugin's default keyspace. Lookup tables inherit the parent's keyspace.
  `TableSchema.keyspace: String?` / `LookupTableSchema.keyspace` and `qualifiedTableName` in `kandra-core`;
  `DdlGenerator` emits qualified names for keyspaced entities.
- `keyspace("name") { autoCreate; replicationStrategy }` in `install(Kandra)` to declare extra
  keyspaces (settings only). An entity naming an undeclared, non-default keyspace fails startup
  with `KandraSchemaException`. A blank default `keyspace` is allowed only when extra keyspaces are
  declared and every entity names one. Declared names must be valid CQL identifiers, unique, and
  different from the default (case-insensitive).
- Per-keyspace bootstrap: keyspace creation, permission validation, DDL for `AUTO_CREATE` /
  `AUTO_MIGRATE` / `VALIDATE`, `system_schema` lookups and DDL locks. The default keyspace keeps its
  original lock table and lock name; each non-default keyspace gets its own `<ks>.kandra_ddl_locks`.
- Runtime emits keyspace-qualified CQL (`billing.invoices`) for entities with a keyspace; metrics and
  debug-log labels use the qualified table name.
- `KandraMigrationRunner(session, staleClaimThreshold, keyspace: String? = null)` and
  `KandraMigration.up(session, keyspace)` (defaults to `up(session)`): `kandra_migrations` and its locks
  are per keyspace.
- Strict-mode replication-factor check resolves the replication of the entity's keyspace.
- `kandra-koin` / `kandra-kodein`: bindings stay per entity; the same-simple-name collision guard now lists
  each class with its `[keyspace: X]`.
- `kandra-codegen` validates the `keyspace` identifier at build time (generated `*Table` objects contain
  no table or keyspace names).
- `kandra-test`: `KandraTestBackend` (shared connection provider; `KANDRA_TEST_BACKEND=docker|cloud`) and
  `KandraCloud` (env-driven live-cluster harness: `KANDRA_CLOUD_CONTACT_POINTS`, `_USERNAME`, `_PASSWORD`,
  `_LOCAL_DC`, `_TLS`, `_CA_PEM`, `_TRUSTSTORE`; TLS on port 9142). Cloud tests skip when unconfigured.
  `KandraTestcontainers.freshKeyspace` honours the backend switch, waits for CQL readiness after container
  start, and all test sessions use 30 s timeouts.

### Changed — Maven group (breaking for dependency declarations)

- The Maven group moves from `ke.co.coinx.kandra` to `com.kandraorm.kandra` (project domain: <https://kandraorm.com>).
  Update dependency declarations; the Kotlin packages (`io.kandra.*`) and all APIs are unchanged. Versions up to
  `0.4.7` remain on Maven Central under the old group. The POM `url` now points to kandraorm.com. Publishing under
  the new group requires the `com.kandraorm` namespace to be verified in the Central Portal first.

### Unchanged / zero regression

- Entities without `keyspace` generate byte-for-byte the same unqualified CQL as before.
- Generated `*Table` objects are identical for keyspaced and non-keyspaced entities.

### Non-goals

- Runtime / per-call / per-tenant keyspace selection.
- Dedicated cross-keyspace batch support (a `batch { }` mixing keyspaces does work, with the usual
  logged-batch cost).

### Opt-in: SimpleStrategy on tablets-enabled clusters

- `ReplicationStrategy.SimpleStrategy(replicationFactor, disableTablets = false)`: when `true`, `autoCreateKeyspace`
  appends `AND tablets = {'enabled': false}` to `CREATE KEYSPACE`, so `SimpleStrategy` works on ScyllaDB clusters
  that enable tablets by default. Default `false`: generated DDL is byte-identical to before. ScyllaDB only
  (Apache Cassandra rejects the `tablets` option). Applies to the default and extra (`keyspace("x") { }`) keyspaces.
- Clusters configured with `tablets_mode_for_new_keyspaces: enforced` reject `SimpleStrategy` entirely, even with
  the flag; use `NetworkTopologyStrategy` there.

### Testing

- Unit: `KandraProcessorKeyspaceTest` (kandra-codegen), `SchemaRegistryKeyspaceTest` (kandra-core),
  `MultiKeyspaceConfigTest` and `CqlSessionBuilderTest` (kandra-ktor: validation, DDL with/without the flag),
  koin/kodein `*MultiKeyspaceTest`, `KandraMigrationMultiKeyspaceTest`.
- Live (Docker/Testcontainers): `MultiKeyspaceRuntimeIntegrationTest` (kandra-test), `MultiKeyspaceIntegrationTest`
  (also runs against the cloud cluster, plain auth, when configured), `SimpleStrategyTabletsIntegrationTest`
  (Docker: Cassandra rejects the `tablets` option; cloud TLS: flagged auto-create through `install(Kandra)`).
- Live (cloud, skipped when `KANDRA_CLOUD_*` is unset): `MultiKeyspaceCloudE2ETest`,
  `SimpleStrategyMultiKeyspaceCloudTest` (skips the `SimpleStrategy` scenario on a tablets-enforced cluster),
  `KandraCloudSmokeTest`.
- Results by backend are recorded in [`docs/test-plan/multi-keyspace-baseline.md`](../test-plan/multi-keyspace-baseline.md).
